# 02 — Prompt : benchmark open source et étude de marché

## Prompt réutilisable

Réalise une étude comparative des projets open source, plateformes, dispositifs et fournisseurs du domaine du monitorage patient et de la télésurveillance médicale.

Le but est de comprendre ce qui existe déjà, ce qui est réellement disponible, les besoins adressés et les possibilités de complémentarité ou de différenciation pour un projet académique de simulation. Il ne s'agit pas de choisir une architecture ni de copier un produit.

### Périmètre de recherche

Étudier séparément :
1. les systèmes de monitorage physiologique hospitalier ;
2. les plateformes de télésurveillance à domicile ;
3. les systèmes de surveillance de dispositifs cardiaques implantés ;
4. les projets open source complets ;
5. les briques techniques open source : génération de données, protocoles, API, interopérabilité, stockage, dashboards ;
6. les fournisseurs commerciaux et les marchés d'achat hospitaliers ;
7. les standards de données et d'échange.

### Pour chaque projet ou fournisseur

Collecter :
- nom et URL officielle ;
- statut open source ou commercial ;
- licence, lorsque pertinente ;
- pays et contexte d'utilisation ;
- pathologies ou types de patients concernés, si documentés ;
- acteurs et rôles ;
- types de données et sources ;
- architecture publique connue ;
- mécanismes de transmission ;
- gestion des alertes ;
- possibilités d'intégration ;
- informations sur le déploiement réel ;
- date des informations consultées ;
- limites et éléments qui n'ont pas pu être vérifiés.

### Évaluation

Classer chaque élément comme :
- solution complète directement comparable ;
- produit commercial spécialisé ;
- brique technique réutilisable ;
- standard ou modèle de données ;
- projet expérimental ou démonstrateur.

Ne pas mettre toutes les solutions dans le même tableau sans cette distinction.

### Recherche de valeur ajoutée

Étudier si les besoins suivants sont déjà couverts :
- génération et rejeu reproductible de scénarios ;
- simulation de défaillances matérielles et réseau ;
- traçabilité complète d'une mesure et d'une alerte ;
- évaluation de la charge d'alertes ;
- démonstration des habilitations et de la sécurité ;
- interopérabilité avec des standards ;
- accessibilité des interfaces patient ;
- test de montée en charge.

Pour chaque piste, préciser les preuves existantes, les concurrents qui la couvrent, les éléments qui restent inconnus et les tests à mener. Ne jamais affirmer qu'une fonctionnalité est unique sans avoir effectué une recherche suffisamment large.

### Étude de marché

Rechercher les marchés publics, centrales d'achat, appels d'offres, fournisseurs, spécialités couvertes, acteurs hospitaliers et modèles de déploiement. Ne pas inventer de taille de marché, de chiffre d'affaires ou de part de marché lorsqu'aucune source fiable ne les fournit.

### Format de sortie

1. Résumé.
2. Carte des segments.
3. Tableau comparatif des projets.
4. Fiches détaillées des références principales.
5. Tableau des technologies et standards.
6. Écosystème commercial et achats hospitaliers.
7. Besoins couverts et zones peu documentées.
8. Pistes de différenciation à tester.
9. Limites de l'étude.
10. Bibliographie avec date de consultation.
